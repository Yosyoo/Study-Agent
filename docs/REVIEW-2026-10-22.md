## 复审结论

上一版具备本地工程闭环，但配置切换、任务入口和失败反馈存在实际缺陷。此前的测试主要覆盖字段填入、保存与预设协议，不能证明首次配置顺畅，也没有覆盖跨厂商回来后的密钥恢复和慢模型确认。这些缺口需要行为修复与工作流回归，不能仅靠增加测试数量解决。

| 问题 | 复现条件 / 影响 | 本次处理 | 对应证据 |
| --- | --- | --- | --- |
| P1 切换厂商删除密钥且丢失自选模型 | 保存另一家预设，再切回来，需要重填 Key，原自选模型被默认值替代 | 每家独立保留配置；Key 绑定厂商与规范化端点，保留且隔离；旧单密钥文件按原配置迁移 | 存储单测、桌面跨厂商/跨地址往返、真实 safeStorage 迁移与重启 |
| P1 任务目标与实际课程可能不一致 | 浏览器已在课程 A，选择课程 B 的任务启动，原实现继续在 A 执行 | 开始时按任务 URL 导航；同 URL 保留页面；恢复继续当前页；创建任务可读取当前页 | 桌面 A → B 流程直接检查最终观察 URL |
| P1 截图 30 秒过期与 90 秒模型超时冲突 | 推理或人工阅读超过 30 秒，即使画面未变也拒绝确认 | 30 秒后重新截图，必须同时匹配控件指纹和图像；5 分钟硬上限 | 真实 Chromium 的 45 秒模拟时差；内容变动时无点击 |
| P1 连接测试不能发现图片被忽略 | 只要回复固定 `ok:true` 即通过 | 随机三个色块读图，期望顺序仅存在图片里；校验模型回答 | 本地 HTTP 实际解码 PNG 返回答案；固定成功回复被拒绝 |
| P2 吞掉具体失败原因 | 401、超时或页面改变都变成“浏览器或模型调用失败” | 保留脱敏后的具体错误；配置页就地显示测试结果；不展示远端原始响应体 | Harness 脱敏测试、桌面真实 HTTP 401 |
| P2 视频存在就跳过练习且启动强制需要 Key | 含暂停视频的练习页被当作监测页；纯视频任务也被 Key 前置检查拦住 | 可见练习优先；实际需要模型时才检查 Key | 混合页面浏览器/状态机测试、桌面无 Key 视频监测 |
| P2 启动期间状态不可取消、结束计时继续增长 | 等待浏览器加载时看不到活跃任务；任务结束仍显示增长的时间 | 打开地址前发布可取消状态；取消后不发模型请求；结束时记录 endedAt | 桌面慢加载中停止、最终时间戳检查 |
| P2 模型页操作负担与空工作台缺少指引 | 厂商按钮叠在大表单上；多处重复状态，首次打开主要看到零值 | 厂商列表与编辑区分开，默认显示模型与密钥，其余折叠；首次工作台提供三个可操作步骤；运行时明确锁定配置 | 实际 Electron 全尺寸和 1100×720 截图检查 |
| P2 重试同一失败页面可能被跳过 | 保留当前 URL 的优化在失败页面也跳过了导航 | 记住失败导航状态，显式重新打开同地址时仍重新导航 | 真实 Chromium 503 两次有限重试后再次打开成功 |

表中最后一项是本轮加入“同 URL 保留页面”行为时发现的回归风险，已在交付前修复并补测；其余项来自对上一版使用流程与代码的复审。

## 验证与仍需验收的范围

最终命令和结果以 [VALIDATION.md](VALIDATION.md) 为准。桌面测试全部用临时资料目录、虚构密钥和本地测试服务。随机图片由本地脚本解码并答复，证明挑战与校验路径有效，**不代表任何真实模型的视觉能力已验收**。

仍需真实学习通与用户模型验收：登录会话复用、实际课程/题目/视频 iframe、混淆字体、任务点完成标记，以及厂商账户的图像支持、响应时延和输出预算。不能把这些事项写成已通过。

仍保留的工程边界：

- 尚未执行 Windows x64、Intel Mac 的实机安装和运行；macOS 本地产物未签名、公证。
- 每家厂商一个配置与一个自定义槽；同一厂商的多个具名配置和模型列表发现尚未实现。
- 图片续验使用严格字节匹配。动态时钟、光标闪动等也可能导致保守拒绝，需要重新观察；不是页面事务锁。
- 已发出的页面加载或单次点击不能保证撤销，停止保证不继续安排后续 Agent 操作。
- 浏览器多标签手动切换仍需注意：当前控制器跟踪最新打开的标签页，界面所示截图和 URL 是确认依据；更完整的标签选择器尚未实现。
- 自动课程导入、无人值守排程、自动答题提交、自动更新仍不属于已交付能力。
